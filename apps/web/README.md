# apps/web

QALoop frontend. Next.js 16 + shadcn/ui + Tailwind, paired with a typed
OpenAPI client generated against `apps/api`.

## Run it

| | |
|---|---|
| Dev (local) | `bun dev` (port 3001) |
| Dev (compose) | `docker compose up web` (port 3000) |
| Prod build | `bun run build && bun run start` |
| Lint / format | `bun lint`, `bun format` |
| Typecheck | `bun typecheck` |

The API URL is read from `NEXT_PUBLIC_API_URL` (build-time-baked).
Defaults to `http://localhost:8001`.

## Layout

```
app/
├── layout.tsx                # AppShell wraps every route
├── onboard/page.tsx          # 3-step "create your first project" wizard
└── projects/
    ├── page.tsx              # project list
    └── [projectId]/
        ├── page.tsx          # project overview
        ├── settings/page.tsx
        ├── testsets/
        │   ├── page.tsx                # feature test list
        │   ├── new/page.tsx            # create feature test
        │   └── [testsetId]/page.tsx    # feature test detail + start a run
        └── runs/
            ├── page.tsx                # run history
            └── [runId]/page.tsx        # the big one: timeline + brief +
                                        # cases + sandbox + scripts + results
```

`app/projects/[projectId]/runs/[runId]/page.tsx` is the heart of the
product — a 2-column layout with a live timeline on the left and a
tabbed content rail on the right (Brief, Test cases, Sandbox activity,
Test scripts, Test results).

```

│   ├── app-shell.tsx         # sidebar + topbar + command palette + mobile gate

│   ├── command-palette.tsx   # Cmd+K search across projects/runs/tests
│   ├── mobile-gate.tsx       # full-screen "open on desktop" below 1024px
│   ├── page-container.tsx    # standard max-width wrapper (1280/880/1440)
│   ├── theme-toggle.tsx
│   └── topbar.tsx            # breadcrumbs + run status badge + theme toggle
└── probe/                    # shared content primitives
    ├── cap-line.tsx          # uppercase section divider
    ├── kbd.tsx               # keyboard chip
    ├── page-head.tsx         # page title + subtitle + actions
    ├── run-status-badge.tsx  # plain-English status pill
    ├── stat-card.tsx         # one big number with a label
    ├── status-dot.tsx        # animated colored dot

```

```
lib/
├── api/
│   ├── client.ts             # openapi-fetch wrapper + type re-exports
│   ├── resources.ts          # one async helper per endpoint
│   ├── schema.d.ts           # generated by `bun run gen:api`
```

## Regenerating the typed API client

```bash
# Make sure apps/api is running on :8001
bun run gen:api
```

This re-runs `openapi-typescript` against `/openapi.json` and overwrites
`lib/api/schema.d.ts`. Add new resource wrappers in `lib/api/resources.ts`
that consume the generated types via `apiClient.GET("/api/...")`.

## Design notes

The visual language is Vercel-leaning: pure-white surfaces in light mode,
true-black surfaces in dark mode, a single near-black accent for primary
actions, no brand color elsewhere. Status tones (ok / warn / err / accent /
muted) carry meaning everywhere.

A few opinions baked into the UI:

- **No mobile / tablet support.** `<MobileGate>` shows a full-screen
  "open on desktop" message below 1024px. The product is dense by nature
  (timeline + content + dialogs); a real mobile experience is its own
  project.
- **One container per page.** `<PageContainer size="default|narrow|wide">`
  is the only horizontal width primitive. Pages don't set their own
  `max-w-*`.
- **Plain-English status everywhere.** Internal node names like
  `agent_2_placeholder` are mapped to phrases like "Sandbox exploration"
  via `lib/labels.ts`. Raw enums never reach the user.
- **Live timeline** is driven by the API's SSE stream. Each event has
  a label, a one-line summary derived from its payload, and the raw
  JSON tucked behind a "Show details" toggle.
